# Button Group

<Lead>A tray of buttons that lights up the chosen ones. Switch between a few options, with a background that slides to the new choice, or turn several filters on and off at once.</Lead>

<DependencyList items={["@ui-sdk/react"]} />

## Example

<Demo name="button-group-filters" />

Press Pending and Paid to show both; press All to clear them. Each lit item gets a solid fill and its LED turns on. Move the pointer along the tray: one hover fill slides from item to item and stays on the last one until the pointer leaves the tray.

## Filters

`selection="multiple"` lets several items stay pressed, and its value is an array of their values. Add `ButtonGroupAll` to give the user a way back to "no filter": it is lit while the value is empty, and pressing it clears the value. Leave it out and an empty value just lights nothing. Counters and other extras go in the item's children.

## Switching

`selection="single"` keeps one item checked, like radios: the arrow keys move the choice, and a background slides to the new item and fades into its fill. Its value is a string, or `null` when nothing is checked, which checks `ButtonGroupAll` if there is one. Set `name` to submit it with a form; with `ButtonGroupAll`, nothing chosen submits nothing and `required` has no effect.

<Demo name="button-group-switch" />

## Icons and tooltips

`icon` renders an icon-only item; name it with `tooltip` (or `aria-label`). `startIcon` and `endIcon` sit beside a label. The LED shows only on text-only items: an icon already marks the item. Items are the registry `Button`, so their tooltip is the Button's.

<Demo name="button-group-icons" />

## Sizes

`size` scales the tray and everything in it: padding, text, icons and LEDs. `"xs"` fits dense toolbars and table headers, `"md"` is the default, and `"lg"` suits a main view switch.

<Demo name="button-group-sizes" />

## Vertical

`orientation="vertical"` stacks the items.

## States

`disabled` works on one item or the whole group. A disabled item still shows its tooltip on hover, so it can say why. In `multiple` the arrow keys still reach it; in `single` the keyboard skips it, like a disabled radio.

## Agents

The group is ready for ui-sdk agents (`createAgent` from `@ui-sdk/react/agent`); find it by its `aria-label`. In `single`, use the group's `setValue` action. In `multiple`, use the group's `toggle` action with the item's value, not the item's label: each item is both ui-sdk's toggle and the registry `Button`, so its label names two entries in the snapshot and pressing it by label is ambiguous.

```ts
await agent.act({
  steps: [
    { ref: "View", action: "setValue", args: ["grid"] },
    { ref: "Status", action: "toggle", args: ["paid"] },
  ],
})
```

```bash
npx shadcn@latest add https://lanzate-ui.vercel.app/r/button-group.json
```

## Usage

```tsx
import { ButtonGroup, ButtonGroupAll, ButtonGroupItem } from "@/components/ui/button-group"

<ButtonGroup selection="multiple" aria-label="Status" value={status} onValueChange={setStatus}>
  <ButtonGroupAll>All</ButtonGroupAll>
  <ButtonGroupItem value="pending">Pending</ButtonGroupItem>
  <ButtonGroupItem value="paid">Paid</ButtonGroupItem>
</ButtonGroup>
```
