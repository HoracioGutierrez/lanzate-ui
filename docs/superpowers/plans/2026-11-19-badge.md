# Badge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `badge` registry component that can build every badge the site has today from one API: the docs "NEW" chip (small, square-ish, soft fill, mono) and the landing pills (round, surface, with a leading tag like "New" / "v0.12.0", text, an optional status dot and an optional trailing icon). Color of the badge and color of its leading tag are set independently. An optional, configurable tooltip.

**Architecture:** A core component (like `Button` and `Text`), composable from parts, no context: `Badge` (root) + `BadgeTag` (the small solid chip in front) + `BadgeDot` (status dot). Parts read the root's size from `data-size` with a `group/badge` variant, so the whole badge stays a Server Component. A badge has no behavior, so ui-sdk ships no primitive for it and none is built: the root uses `renderElement` from `@ui-sdk/react/primitive` (as `Text` does) for `render`. The only behavior is the optional tooltip, which reuses the registry `Tooltip` exactly as `Button` does.

**Tech Stack:** React 19, Next.js, Tailwind v4, `class-variance-authority`, `@ui-sdk/react` (`primitive`, `tooltip`, `agent` in tests), Vitest + Testing Library.

## API

```ts
// badge.types.ts
export type BadgeColor = IntentColor                      // primary | secondary | muted | info | success | warning | error
export type BadgeVariant = "solid" | "soft" | "outline" | "surface"
export type BadgeSize = "sm" | "md"                       // sm = docs chip (text-3xs), md = landing pill (text-xs)
export type BadgeRadius = "none" | "sm" | "md" | "full"   // docs: "sm"; landing: "full"
export type BadgeFont = "sans" | "mono"

export type BadgeTooltipOptions =
  Pick<TooltipProps, "delay" | "toggleable" | "type"> &
  Pick<TooltipContentProps, "side" | "align" | "sideOffset" | "arrow" | "className">

export type BadgeProps = {
  color?: BadgeColor          // default "primary"
  variant?: BadgeVariant      // default "soft"
  size?: BadgeSize            // default "md"
  radius?: BadgeRadius        // default "full"
  font?: BadgeFont            // default "sans"
  /** Wraps the badge in a Tooltip. A badge that isn't already a link or button becomes a focusable button so the tip is reachable by keyboard and touch. */
  tooltip?: ReactNode
  tooltipOptions?: BadgeTooltipOptions
  className?: string
} & Omit<PartProps<"span">, "color" | "className">

export type BadgeTagProps = {
  color?: BadgeColor          // default "primary", independent of the Badge's
  variant?: Exclude<BadgeVariant, "surface">  // default "solid"
  className?: string
} & Omit<PartProps<"span">, "color" | "className">

export type BadgeDotProps = {
  color?: BadgeColor          // default "primary"
  /** Pulses, for live states. Off under prefers-reduced-motion. */
  pulse?: boolean
  className?: string
} & Omit<PartProps<"span">, "color" | "className">
```

Variants (`satisfies Record<Union, string>`, every class a token utility):

- `solid`: `bg-{c} text-{c}-foreground`
- `soft`: `bg-{c}/15 text-{c}` (the docs chip)
- `outline`: `border border-{c}/40 text-{c}`
- `surface`: `border border-border bg-card/70 shadow-soft backdrop-blur` + text tinted by color (`muted` → `text-muted-foreground`, the landing pill)
- Root sizes: `sm` → `gap-1 px-1 py-0.5 text-3xs`; `md` → `gap-2 px-3 py-1 text-xs font-medium`
- Root with a leading tag: `has-[>[data-slot=badge-tag]:first-child]:ps-1` (CSS `:has()`, Baseline 2023) so the pill hugs the chip like today's `pl-1`.
- `svg` children: `[&_svg]:size-3 [&_svg]:shrink-0`
- Interactive root (rendered as `a`/`button`, or tooltip): `transition hover:bg-accent focus-visible:outline-2 focus-visible:outline-ring` via `[a&]:` / `[button&]:` variants, `motion-reduce:transition-none`.
- `BadgeTag`: follows the root's radius one step smaller through `group-data-[radius=…]/badge:` (`full` → `rounded-full`); `px-2 py-0.5 text-3xs font-semibold tracking-wide uppercase` (`sm` root: `px-1`).
- `BadgeDot`: `size-1.5 rounded-full bg-{c}` (`aria-hidden`), pulse `motion-safe:animate-pulse`.

Data attributes: root `data-slot="badge"`, `data-color`, `data-variant`, `data-size`, `data-radius`; parts `data-slot="badge-tag"` (+ `data-color`, `data-variant`), `data-slot="badge-dot"`.

### Composition → outcomes

```tsx
// Docs chip (title eyebrow and sidebar)
<Badge size="sm" radius="sm" font="mono">New</Badge>

// Hero
<Badge variant="surface" color="muted" render={<a href="#changelog" />}>
  <BadgeTag>New</BadgeTag>
  v{VERSION} · 4 accessible components
  <ArrowRight aria-hidden="true" />
</Badge>

// Footer
<Badge variant="surface" color="muted" className="bg-card/30 shadow-none">
  <BadgeTag>v{VERSION}</BadgeTag>
  <BadgeDot />
  All operating systems
</Badge>

// Independent colors + tooltip
<Badge variant="outline" color="info" tooltip="Released Nov 18" tooltipOptions={{ side: "bottom" }}>
  <BadgeTag color="success">Stable</BadgeTag>
  v0.12.0
</Badge>

// Full control: compose the Tooltip yourself (Badge forwards props, ref and render)
<Tooltip toggleable>
  <TooltipTrigger render={<Badge render={<button type="button" />} />}>Beta</TooltipTrigger>
  <TooltipContent side="right">May change before 1.0</TooltipContent>
</Tooltip>
```

### Tooltip decisions (ui-sdk)

- Reuse `@/components/ui/tooltip/tooltip` + `tooltip-content` (exact-file imports, decision 0003) and `TooltipTrigger` from `@ui-sdk/react/tooltip`, as `button.tsx` does.
- A tooltip trigger must be focusable (`docs/components/tooltip.md` → Custom Rendering, Touch). So when `tooltip` is set:
  - no `render` → the badge renders as `<button type="button">` (still `data-slot="badge"`), and the Tooltip defaults to `toggleable` so a tap shows it on touch screens and its text is announced;
  - `render` given (a link) → `TooltipTrigger render={badgeEl}`, `toggleable` defaults to false (pressing follows the link).
- `tooltipOptions` passes through the props a consumer would reasonably tune; anything more → compose by hand (last example above).
- Agent-ready: a badge with a tooltip is a trigger the bridge sees; it's named by its visible text, so no `aria-label` is needed. A badge with no text (dot only) must get `aria-label`; documented, and tested.

## Global Constraints

- Repo rules in `AGENTS.md` and `src/components/ui/AGENTS.md`: one component per file, types only in `badge.types.ts`, class maps in `badge.variants.ts`, named exports, `cn` from `@/lib/cn`, no literal design values, kebab-case.
- **Server Component by default**: no `"use client"` in `badge.tsx`, `badge-tag.tsx`, `badge-dot.tsx`. Tooltip parts are client modules already; rendering them from a server component with an element prop is fine. Verify with `next build` (Task 4).
- Badge is a **core** component: add it to the core list in `src/components/ui/AGENTS.md` and `docs/architecture/registry.md#building-on-core-components`.
- Text inside a badge needs 4.5:1 contrast: check `soft` and `outline` for every intent in light and dark in the browser (jsdom can't). `warning`/`success` on `/15` are the risky ones.

## Decisions

1. The leading chip is `BadgeTag`.
2. Colors are intents only; the site's badges use `primary`, not `brand`. `brand` is a `site`-scope token, so a registry component can't use it (consumers don't get it). On this site `primary` and `brand` are the same color in both modes, and the site applies no theme class, so the migration is visually identical. In a consumer app using `.theme-ocean`/`.theme-sunset`, the badge follows that theme's `primary`, like every other registry component.
3. `BadgeDot` ships with `pulse`. The docs page gets a `pulse` demo (`badge-dot.demo.tsx`: a "Live" / "Deploying" badge with a pulsing dot next to a static one), and the reduced-motion note.
